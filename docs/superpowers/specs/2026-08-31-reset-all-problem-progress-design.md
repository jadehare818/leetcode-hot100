# 一键重新开始全部题目——设计说明

## 目标

用户已经刷完过一轮题目，希望开始新一轮复习。执行一次批量操作后，当前题库中的所有题目都重新进入未刷池，由每日配额逐步安排；上一轮的状态、复习档位和已有资料继续保留。

## 当前系统

已验证的现状：

- `status` 决定题目处于未刷池、复习池或归档状态。
- `review_stage` 决定复习间隔；未开始的题使用 `-1`，已进入复习调度的第一档使用 `0`。
- `history` 保存首刷、复习、推迟和归档等动作，但现有事件不直接保存每次操作前后的档位。
- 日历和连续天数从完整 `history` 统计；每日新题配额和本轮完成进度从当前状态及当日历史统计。
- 题目笔记、Cheatsheet 和代码文件引用与调度状态保存在同一条进度记录中。

```text
当前题库（官方题 + 未删除的自定义题）
             │
             ▼
        progress 记录
   ┌─────────┴─────────┐
   │                   │
当前调度字段         长期资料与历史
status/stage/next    note/cheatsheet/code/history
   │                   │
本次清零              本次保留
```

## 用户操作流程

1. 用户打开设置弹窗。
2. 在“重新开始”区域点击“重新开始全部题目”。
3. 浏览器显示确认信息，明确说明所有题会回到未刷池，历史、笔记和代码不会删除。
4. 用户确认后，前端调用批量重置接口并暂时禁用按钮，避免重复提交。
5. 服务端处理当前有效题目并原子写回进度文件。
6. 页面刷新。今日看板按每日配额从未刷池重新选题，复习到期列表清空。

## 数据设计

### 重置事件

对每道已经有当前进度的有效题目，在原有 `history` 末尾追加事件：

- `date`：按应用的每日结束时间计算出的业务日期。
- `action`：固定为 `reset-all`。
- `previous_status`：重置前的状态。
- `previous_review_stage`：重置前的复习档位。
- `previous_next_review`：重置前的下次复习日期。
- `previous_last_done`：重置前的最近完成日期。

事件在当前字段被清零前写入，因此旧档位可以直接从历史中读取。已经处于未刷状态且没有本轮进度的题目无需新增重复事件，重复请求不会连续制造相同的重置记录。

### 当前字段

重置后只修改调度字段：

- `status = "todo"`
- `review_stage = -1`
- `next_review = ""`
- `last_done = ""`

保留以下内容：

- 完整 `history`，包括新增的 `reset-all` 事件。
- `note` 和 `cheatsheet`。
- `code_file`、`code_files` 及磁盘上的题解文件。
- 未识别的附加字段，避免破坏旧版本或后续版本的数据。

只处理 `load_problems()` 返回的当前有效题目。已软删除的自定义题留下的孤立进度保持原样。

## 当前轮次与终身统计

两类统计采用不同范围：

- 当前轮次：每日新题配额、今日完成题和“本轮全部完成日期”只读取每道题最后一次 `reset-all` 之后的 `solve`、`review` 或 `archive` 事件。
- 终身记录：Calendar、历史做题量和连续天数继续读取全部 `solve`、`review` 事件，重置不会抹掉过去的打卡记录。

同一天先做题再重置时，重置前的动作仍保留在日历中，但不会占用新一轮当天的新题配额。同一天重置后再完成的题会正常计入新一轮。

## 接口与界面

新增 `POST /api/progress/reset-all`：

- 不接收客户端传入的题目 ID，服务端自行读取当前有效题库，避免漏题或越权修改孤立记录。
- 成功返回 `ok`、当前有效题目总数和实际重置数。
- 保存继续使用现有的临时文件替换方式，写入过程中失败不会留下半份 JSON。

入口放在全局设置弹窗底部，使用独立的警示区域。确认弹窗只出现一次；请求进行时禁用按钮。接口失败时保留当前页面并显示错误，成功后刷新页面。

## 具体例子

#1 当前数据为 `solid / stage 4 / next_review 2026-09-01`，并已保存笔记和 Python 题解。重置后：

- `history` 新增一条 `reset-all`，其中 `previous_review_stage` 为 `4`。
- 当前字段变为 `todo / stage -1 / 无 next_review`。
- 笔记、题解和此前所有刷题事件不变。
- #1 回到未刷池，轮到每日配额选中后再进入新一轮复习。

## 错误处理与边界

- 空题库：接口成功返回，重置数为 `0`。
- 无进度的题：本来就等价于未刷，不创建无意义记录。
- 已归档题：记录归档前状态和档位，然后回到未刷池。
- 连续点击或网络重试：重置后的题不再次追加相同事件。
- 进度文件含已删除题目：不修改该记录。
- 保存失败：接口返回错误；前端不刷新并恢复按钮。

## 测试

- 单元测试重置函数：旧档位进入历史，当前调度字段清零，笔记和代码字段保留。
- 单元测试重复重置：第二次调用不新增重复事件。
- 单元测试题目范围：有效官方题和自定义题被处理，孤立进度不变。
- 单元测试同日边界：重置前的完成不占新一轮配额，重置后的完成正常计数。
- 单元测试本轮完成日期：只使用最后一次重置后的完成事件。
- Flask 接口测试成功响应和持久化结果。
- 手动验证设置入口、确认提示、失败提示和成功刷新。

## 不在本次范围内

- 不提供恢复到上一轮当前状态的一键撤销功能。
- 不新增多轮进度对比页面。
- 不改变单题状态下拉框现有的“未刷”行为。
- 不重置设置、题目资料、代码文件或日历记录。
