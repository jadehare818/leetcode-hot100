# Story — checkin-post-completion-blurb

## 需求理解
打卡卡片只在当前有效题集首次全部完成的当天展示一次庆祝语；从第二天开始，不再因“当前仍然全部完成”而重复庆祝，普通推荐语主要表达坚持复习、保持手感。同时保留现有连续天数 / 连续周数里程碑文案，且不改变卡片接口、完成口径或分享链路。

## 验收标准 (AC)
- [ ] AC-1：当当前有效题集全部为非 `todo`，且按每题最早 `solve/archive` 历史推导出的全部完成日等于业务当天时，`/api/checkin` 返回一次“100 题首战告捷，恭喜！”。
- [ ] AC-2：当当前有效题集已在更早日期全部完成、当前 streak 不命中里程碑时，`/api/checkin` 返回复习主题文案池中的文案，且不返回庆祝语。
- [ ] AC-3：全部完成后的 streak 为 3 天、5 的正倍数或 7 的正倍数时，仍返回现有连续天数 / 连续周数里程碑文案；7 的倍数继续优先按周展示。
- [ ] AC-4：在全部完成后的日期重标一道人为 `forgot/shaky/solid`、从而新增一次 `solve` 历史时，不会再次返回庆祝语。
- [ ] AC-5：完成历史缺失或日期非法时，系统采取保守策略，不把当天误判为首次全部完成，也不导致 `/api/checkin` 报错。
- [ ] AC-6：当题集尚未开始时仍返回起点文案；当题集尚未全部完成时，既有通用随机池和无活动兜底行为保持原有语义。

## 不变量 (Invariants) — 本次改动不得破坏
- INV-1：`/api/checkin` 的响应字段与字段类型不变；`static/checkin.js`、保存图片、飞书和定时截图调用方无需修改。
- INV-2：“全部完成”继续表示当前存活的官方题和自定义题中没有 `todo`；`forgot/shaky/solid/archived` 均计入已完成。
- INV-3：业务日期继续使用 `_today()`，遵循 `day_boundary_hour` 配置。
- INV-4：计算首次全部完成日时只扫描当前有效题目 ID，忽略已软删自定义题留下的孤儿进度。
- INV-5：完成当天的庆祝语优先于同日 streak 里程碑；完成后的 streak 里程碑优先于复习主题随机池。

## 我注意到的关键边界 / 已知约束
- 当前题集为动态集合；以后新增自定义题并再次完成全部当前题目时，会产生新的“当前题集首次完成日”并再次庆祝一次。
- 把题目重置为 `todo` 会清空该题历史，因此本方案只能准确推导当前这轮题集的完成日，不能恢复重置前的一生首次完成记录。
- 手动 `archive` 在现有完成口径中等价于非 `todo`，因此 `archive` 事件也参与完成日推导。
- 删除最后一道未完成的自定义题不会产生 `solve/archive` 事件；在无法证明首次完成日时不庆祝。
- 当前仓库没有既有自动化测试目录，本次使用 Python 标准库 `unittest` 增加最小表驱动测试，不新增依赖。

## 我没想清楚 / 想和你确认的
- 无。已确认：完成后保留连续天数 / 连续周数里程碑，其余推荐语转为复习主题。
